# mm-write-short-drama v1.3.0

发布日期：2026-11-19。[正式版本](https://github.com/CodeBlueFriend/mm-write-short-drama/releases/tag/v1.3.0) · [完整变更记录](../../CHANGELOG.md) · [当前设计](../current-design.md)

本版支持先试写一场或局部改对白，也把正式项目从规格选择、大纲确认、分批写作到 Word 验收连成可恢复的工作流。已有插件入口、知识库和旧版兼容工具继续随包提供。

## 先试写，再决定是否立项

```text
$mm-write-short-drama 只试写一场：母亲想要回女儿攥着的旧房钥匙，女儿还不知道母亲已经退租。两个人、一张桌子，先给候选正文。
```

试戏或局改直接交候选场次，沿用原稿格式，只补读相关锁定事实、人物知情边界和上场结尾；不要求先建整季项目、迁移状态或导出 Word。采纳后按正式项目审核和版本流程并入，不把试稿采纳等同于整季大纲确认。只要求审核时给原文依据和诊断，不擅自改稿。

默认由当前会话模型主笔。用户明确选独立主笔时，可委派项目配置的 `drama_writer`，主会话提供必要事实、审稿并原样交付获选稿，表达返修送回同一主笔。项目级示例 [.codex/agents/drama-writer.toml](../../.codex/agents/drama-writer.toml) 使用 `gpt-6.2-astra` 与 `medium`；复制到实际写作项目并加载后才生效，只安装技能不会自动加载该项目配置。模型不可用或委派失败应如实报告。[主笔指南](../../mm-write-short-drama/references/lead-writer.md)

## 正式项目的新流程

新建时按“AI或真人 → 创作来源 → 题材等需求 → 单集时长 → 期望集数”取得真实选择。来源支持自己编写、已有素材改编、检索近期热门剧本后改编/再创作；旧素材再创作路由保持兼容。制作方式、来源、时长和期望集数缺一项就停在当前等待点，题材等普通需求可先待定，不默认真人6集。

三路均先把故事从开头讲到结局，通读底稿，再形成可独立判断的大纲。严格、辅助和自动模式都等待创作者明确确认当前大纲版本；“继续”或自动推进不能代替确认。用户期望集数与大纲实际总数分开记录，实际数偏离期望时说明剧情理由，随大纲确认。上游变化使关联批准和审读失效。

默认每批3—5集。审稿第一遍只读正文并记录理解与卡点，第二遍再对照来源、大纲和连续性账本；最终交付还须覆盖实际本批或全剧。逐集状态、真实问题单、版本和覆盖共同决定能否批准，手填问题数为零不能绕过阻断。[命令行使用手册](../usage.md)

## 方法、润色与 Word

- 随包固定五书24份方法摘要，覆盖前四书5项与麦基《故事》19项能力，保留来源版本、原始摘要哈希与核验边界；它们不是原书全文。个人已启用卡优先，当前随包摘要兜底，v1.2.2三张公开卡保留兼容。旧六张《故事》卡按显式迁移与归档处理，不覆盖私人库。
- 润色默认 `local`，只改具体表达问题；可选 `off` 原样复核，`full` 仅在项目明确选择后使用。`polish_guard.py` 记录前后稿差异、实际调用链和最终语义复核。随包 Humanizer 规则、许可与旧工具保留为可选兼容适配器；旧校验通过不能替代人物、金额、日期、否定、条件和承诺的实际对读。
- 正式 Word 每批合并一份，首集前包含当前项目九项前置模块。`--project-dir`、`--front-matter` 和有效审核是正式导出的必要输入；先写暂存区，再实际渲染、逐页检查并用 `--publish --visual-qa` 发布。`--preview` 明示预览，不占正式状态。正文、前置或上游变化后重新审核和验收，既有正式件不覆盖。[Word 交付规则](../../mm-write-short-drama/references/word-delivery.md)

插件方式继续使用：

```bash
codex plugin marketplace add CodeBlueFriend/mm-write-short-drama
codex plugin add mm-write-short-drama@short-drama
```

需要固定版本时，在 Codex 输入：

```text
$skill-installer 从 https://github.com/CodeBlueFriend/mm-write-short-drama/tree/v1.3.0/mm-write-short-drama 安装技能
```

也可克隆 `v1.3.0`，将仓库中的 `mm-write-short-drama/` 内容复制到实际使用的技能目录。重新开启 Codex，使技能列表刷新。[完整安装步骤](../../README.md#安装与升级) · [插件隐私说明](../plugin-privacy.md)

## 升级与兼容

升级前备份原技能目录及自己修改的文件，只更新程序和通用资源。项目、原著、私人知识库、原模板及历史交付保持原位置。旧项目可先只读诊断；正式续作前明确迁移映射与缺失证据，不能把旧 `approved` 或无法证明的确认当作新版已通过。

旧 `--mode source-remix`、A/B/C内部审核阶段、连续性账本与原始资料留存继续兼容。`init --mode` 只决定空骨架，不算用户已选来源。旧直接 Word 导出命令用于正式交付时须补项目、前置内容和当前审核；纯版式可明确使用 `--preview`。

运行需要 Python 3.10+，Word 构建需要 `python-docx`；实际渲染还需可用文档渲染器、Pillow 和 PyMuPDF 或 pypdf。优先使用 Codex 工作区依赖，不在未说明时重复安装外部 Humanizer。独立主笔需账号实际可用的模型与已加载项目配置。

技术回归验证工作流和版本约束，不证明某种写法或模型必然更好。独立主笔的实际加载、模型对比和完整匿名选版以真实执行记录为准；本版不宣称已经完成这些效果实验。
