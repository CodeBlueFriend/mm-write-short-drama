# mm-write-short-drama v1.2.0

发布日期为 2026-11-18。

## 新增功能

- **项目状态与依赖追踪**。从 `.drama/` 恢复创作进度，按集记录计划、草稿、审核和批准状态。修改上游材料前，可预览受影响的产物。确认后将相关产物标记为 `stale`，并记录复审范围。
- **连续性和审核**。新增关系、证据和独立伏笔账本。审核问题使用 P0–P3 等级，记录证据、影响范围和复检要求。
- **五项写作能力检索**。支持按能力 ID 补查梗概、结构、人物秘密、集间兑现和对白行动规则，保留来源和核验范围。
- **批次合并 Word**。用基础模板将每批全部集数按集号合并为一个 `.docx`。模板提供宋体、标题和正文样式、对白分色及自动页码。可用 `--front-matter` 加入当前项目已审核的前置材料。

## 从 v1.1 升级

按 [README 的稳定版安装步骤](../../README.md#方法一安装稳定版-v120) 获取 `v1.2.0` 标签，并更新 `mm-write-short-drama/` 技能目录。已有项目和个人知识库继续放在原工作区。缺少 `.drama/` 或仍使用旧账本字段的项目，整季续作前先核对字段和状态，再按确认后的迁移方案处理。局部改稿可以直接使用现有文本。

项目和知识库工具需要 Python 3.10 或更新版本。Word 导出另需 `python-docx`。正式剧本交付使用单独安装的 `humanizer` 与 `mm-humanizer-gate`，并按交付流程渲染检查最终 Word。

## 命令示例

在仓库根目录生成项目状态检查和上游影响报告。

```bash
python3 mm-write-short-drama/scripts/validate_state.py ./projects/example
python3 mm-write-short-drama/scripts/impact_analysis.py ./projects/example \
  --changed 04-story-bible.md --json
```

将已审核的两集剧本导出为一个 Word 文件。

```bash
python3 mm-write-short-drama/scripts/export_screenplay_docx.py \
  ./projects/example/episodes/EP001.md ./projects/example/episodes/EP002.md \
  --output ./projects/example/deliverables/示例项目_第01-02集.docx \
  --project-title 示例项目
```
