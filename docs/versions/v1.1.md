# mm-write-short-drama v1.1

发布日期：2026-08-14

版本号：`1.1.0`

v1.1 完整保留 v1.0 的短剧创作与改编工作流，并新增“个人编剧知识库系统”。核心原则是：Skill 负责稳定工作流，`knowledge-base/` 负责持续增长的个人编剧知识，两者分开管理和升级。

## 新增功能

- 六区知识库：Inbox、原始资料、知识卡、索引、冲突记录和归档。
- 原子知识卡：一张卡只表达一条可判断、可调用的编剧规则。
- 双入口录入：Codex 对话直接粘贴文字，或批量处理 Inbox 中的 Markdown/TXT。
- 自动处理：保存原文、初步分类、标注适用范围、查重、查冲突和更新索引。
- 冲突治理：疑似冲突进入 `pending-conflict`，经用户裁决前不得用于创作。
- 阶段化调用：策划、结构、分集、场景、对白、改编和审核阶段分别检索相关规则。
- 可审计输出：审核报告可列出实际使用的规则 ID。
- 可移植存储：知识卡使用 Markdown，索引和日志使用 JSONL，不引入向量数据库。

详细数据结构、状态机和流程图见 [个人编剧知识库系统设计](../knowledge-base-design-v1.1.md)。

## 从 v1.0 升级

先备份自己修改过的旧 Skill，再更新仓库并复制新版 Skill：

```bash
git pull --ff-only
cp -R ./mm-write-short-drama ~/.codex/skills/mm-write-short-drama
```

知识库必须保留在长期工作区，不要放进 `~/.codex/skills/mm-write-short-drama/`。升级 Skill 时只替换 `mm-write-short-drama/`，不要覆盖已有 `knowledge-base/` 和短剧项目目录。

首次使用时校验空库并生成索引：

```bash
python3 mm-write-short-drama/scripts/validate_knowledge.py \
  --kb ./knowledge-base \
  --fix-index
```

## 日常录入一条技巧

直接录入一条已经提炼并确认启用的规则：

```bash
python3 mm-write-short-drama/scripts/ingest_knowledge.py \
  --kb ./knowledge-base \
  --text "主角第一次有效反击必须改变资源、关系或信息状态，不能只获得口头胜利。" \
  --rule "主角第一次有效反击必须改变资源、关系或信息状态，不能只获得口头胜利。" \
  --source-name codex-conversation.md \
  --title "首次有效反击" \
  --category "分集与卡点" \
  --stage episode \
  --genre "女频复仇" \
  --production-mode all \
  --priority preferred \
  --status active
```

如果原文尚未拆成原子规则，先保存为草稿：

```bash
python3 mm-write-short-drama/scripts/ingest_knowledge.py \
  --kb ./knowledge-base \
  --text "这里粘贴课程、文章或自己的编剧总结" \
  --source-name lesson-12.md
```

也可以在 Codex 对话中说：

```text
$mm-write-short-drama 把下面这段编剧技巧录入 ./knowledge-base。
必须保留原文，拆成原子规则，自动分类并标注适用范围；
先查重和查冲突，任何冲突都等我确认，不得覆盖旧规则：
（在这里粘贴技巧原文）
```

## 批量录入多期资料

把 `.md` 或 `.txt` 放入 `knowledge-base/inbox/`，然后运行：

```bash
python3 mm-write-short-drama/scripts/ingest_knowledge.py \
  --kb ./knowledge-base \
  --all-inbox
```

Inbox 原文件不会被移动、改名或删除。脚本会将不可变原文副本写入 `sources/`；重复和冲突分别写入日志，不会静默覆盖旧知识卡。

## 检索与调用

```bash
python3 mm-write-short-drama/scripts/search_knowledge.py \
  "女主第一次反击和本集结尾卡点" \
  --kb ./knowledge-base \
  --stage episode \
  --genre "女频复仇" \
  --production-mode live-action \
  --limit 8 \
  --format context
```

默认只检索 `active` 规则。当前项目要求和锁定事实优先；`draft`、`pending-conflict`、`deprecated` 和 `archived` 默认不参与创作。

## 冲突裁决

先在 `knowledge-base/conflicts/conflicts.jsonl` 中找到冲突 ID，再选择：

```bash
# 保留旧规则，新规则不启用
python3 mm-write-short-drama/scripts/ingest_knowledge.py \
  --kb ./knowledge-base \
  --resolve KBC-XXXXXXXXXXXX \
  --decision keep-existing

# 启用新规则，旧规则会留下状态变化记录
python3 mm-write-short-drama/scripts/ingest_knowledge.py \
  --kb ./knowledge-base \
  --resolve KBC-XXXXXXXXXXXX \
  --decision activate-new
```

若选择 `keep-both`，必须用 `--note` 明确两条规则不同的适用范围。

## 上传小说改编示例

小说正文属于具体项目素材，不要放入个人编剧知识库：

```text
$mm-write-short-drama 把我上传的 novel.md 改编成 24 集竖屏真人短剧，单集 90 秒。
个人知识库使用 ./knowledge-base。
先索引全文，区分原著事实、合理推断、改编决定和待确认项；
只检索 adaptation、都市情感、live-action 相关的 active 知识卡。
本轮只交付原著事实库、改编映射和故事圣经，不写分集和剧本。
审核摘要列出实际使用的知识规则 ID。
```

## 根据思路原创短剧示例

```text
$mm-write-short-drama 根据这个思路原创 6 集竖屏都市悬疑短剧：
一位便利店夜班店员替陌生人保管秘密，最后发现秘密都指向同一场旧案。
低成本真人拍摄，单集 90 秒，结局温暖但不能靠巧合。
使用 ./knowledge-base，只检索 planning 阶段、都市悬疑、live-action 相关的 active 规则。
严格确认模式，先完成项目启动单、原创故事发现和故事圣经；不要直接写分集。
说明实际使用了哪些知识规则 ID。
```
