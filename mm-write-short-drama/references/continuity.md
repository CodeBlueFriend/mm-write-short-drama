# 连续性与上下文装配

## 单一事实源

聊天和模型摘要不作为事实源。采用五层状态：L0 用户锁定不可变事实；L1 已审核事实；L2 当前计划；L3 临时候选；L4 已废弃。冲突时以最新批准的项目文件和变更记录为准。

## 六类账本

| 文件 | 最低记录内容 |
|---|---|
| `canon.yaml` | 世界、人物、关系、禁改项、事实层级和来源 |
| `timeline.csv` | 日期、时刻、事件、地点、参与者、持续时间、来源集 |
| `character-state.csv` | 每集末身体、情绪、关系、资源、目标、状态 |
| `knowledge-state.csv` | 角色、事实、获知集/场、来源、确定性 |
| `props-ledger.csv` | 道具、持有人/地点、状态、转移事件、最后确认位置 |
| `hooks-ledger.csv` | 钩子/伏笔、建立、推进、预计/实际回收、状态 |

所有 ID 保持稳定。旧事实失效时标记 superseded/废弃并引用变更项，不直接抹掉历史。

## 最小上下文包

某批次只装配：项目启动单；故事圣经相关片段；当前整季阶段；当前批次分集卡；上一批最后两集状态摘要；涉及人物的最新状态/信息；未回收伏笔；相关技巧；用户最新批注。

运行 `build_context_pack.py` 后人工核对是否遗漏关键人物、道具或上游锁定项。上下文包是便利副本，不取代源账本。

## 审核方法

逐场比较“进入状态 → 行动 → 离开状态”，并检查：

- 人物身体能力与伤病；
- 日夜、日期、路程和持续时间；
- 角色是否提前知道秘密；
- 道具持有人、损坏和去向；
- 称呼与关系是否匹配当前阶段；
- 伏笔承诺是否推进/回收；
- 已废弃方案是否重新出现。

问题必须附具体集/场、账本行或事实 ID。跨集修改前先做传播分析，批准后只重审受影响范围及其后续依赖。
