# 五项写作能力与练习入口

本文件定义项目调用接口，不代表四本书完整正文已获核验。按需求和稿件证据挑方法，不要求用户报书名。书籍归属与可见范围以检索卡中的 source_note、source_verification 为准；目录主题不能作为具体方法的原书依据，交接包的操作步骤和示例须标为短剧适配/项目实践。

## 选择方法

先确定交付物：梗概、结构、分集、场次、局部改稿、编审或练习。摘录本轮问题的原文证据，再按下表选择阶段与查询。整季任务分阶段加载；单点改稿通常只用一至两项。表内是原仓颉 ID，实际卡 ID 从索引取得，不另造同义 ID。

| 证据/需求 | 检索阶段与能力后缀 | 执行动作与交付 |
|---|---|---|
| 创意只能说出题材，主角要做什么不清楚 | planning；cap.save-the-cat-short-drama.logline | 摘出主角、触发、目标、阻力、失败代价，用已有事实写一句梗概；新设定标候选，不把推测锁定。需要取舍时最多三种实质不同的方案。 |
| 中段反复、结局无铺垫、搭整季 | structure；cap.save-the-cat-short-drama.beat-sheet | 转折逐项写前因→人物选择/行动→改变的条件，映射当前集数和时长；不强制电影页码比例或每集套十五节点。 |
| 隐瞒影响人物行动、反转凭空添加事实 | structure/episode；cap.tv-showrunner-roadmap.character-mystery | 记录事实、人物知情范围、观众知情范围、可见线索、揭露点与揭露后的选择；交付受影响场景，不让角色提前知道真相。 |
| 上集留钩子，下集没接；卡点重复同一威胁 | episode；cap.short-drama-basics.payoff-turns | 对读上集承诺与下集第一行动，写可替换的集尾和开场；延期时明确当集进展及后续兑现点，不能只推迟答案。 |
| 台词太直、同声同气、关键对质不推进 | dialogue/scene；cap.mckee-dialogue-short-drama.verbal-action | 明确双方想让对方做什么、各自隐瞒什么；改关键几轮“策略→反应→换策略”，保留声纹，以行动或关系变化验收。 |

先用自然语言问题做 search_knowledge.py 的任务查询并传入阶段/题材/制作形式。已确定能力但自然语言未命中时，可用 `--capability <原ID>` 和空查询精确检索，仍只取 active，检查卡例外后再用。这是语义诊断后的补查，不按关键词强制启动。`draft` 只供显式审核，不用它生成用户稿件。

## 范围与连续性

读取本轮涉及的身份、目标、关系、时间、秘密、人物/观众认知、伏笔、兑现点、集长与制作限制。有账本则复用，没有则从当前稿摘取最低必要事实，不要求局部修台词先建立整季工程，也不自动迁移旧项目。

优先解决直接造成当前问题的上游原因，但局部授权不允许擅改已确认设定。先交付范围内可用版本；必须改变锁定事实的做法列备选并走既有影响分析/确认流程。按“用户目标与锁定事实→硬约束→卡适用范围”处理方法冲突。对白修订后检查动机、因果、知情边界、伏笔和承诺，并只同步实际受影响的账本。

轻喜剧合作、无隐瞒驱动的戏，不为了调用秘密卡制造秘密；只顺已经确认的台词，不改转折/身份/集尾兑现。即使场景有秘密，也不意味着纯措辞任务需要改揭露结构。无适用卡时回到原流程。

正常写作先交可替换正文。编审默认“原文证据→判断→可执行改法→短示范”，不得把整稿返修当默认授权。已有版本质量足够则保留，不为展示方法强改。剧本 Word 合并、Humanizer、原有审核门保持不变。

## 教学复练

“教我写/为什么这样改/练一题”复用同一批卡：指出一处原文问题，给短对照示范，布置一个能自查的练习；下轮按同一标准反馈。卡点练习可以只写下一集开头三句，验收是否承接旧承诺、有可见进展和下一行动。不要把正常改稿变成先做作业。

## 调试记录

调试/验收时记录：输入、入口版本、已确认事实、实际检索命令及返回 ID、采纳/跳过理由、原文证据、改稿位置、改后状态与复检结果。检索返回不等于已使用，字段测试不等于创作质量通过。区分“材料就绪、卡已激活、正常入口调用、创作效果”四项。原包 examples.md 用于兼容检查，新增面馆用例用于新素材验证。

## 导入和来源维护

先在隔离库导入 draft，逐卡复核原子粒度、重复冲突、来源覆盖范围、原创正反例和执行字段。沿用 rule 哈希 ID；capability_id 保存原仓颉 ID；多卡可共享一个 capability_id。来源文件及 SHA 不变，复核补充用 archive_and_update 留版本，rebuild_index 更新索引。重跑遇到等价卡复用并记映射，不能用重新导入 active 偷渡升级 draft。存在来源不足或冲突的规则保持 draft/pending-conflict，明确影响。

来源仅公开目录的实务方法可作为明确署名为“交接包项目实践”的卡审核，不能说是原书已核原则；若仍主张原书归属而无依据，不能激活。完整章节、版次或页码未取得就写待核。独立 Skill 保留自己的入口与来源边界，主 Skill 日常调用本库已审核卡，不必同时加载四个独立入口。
